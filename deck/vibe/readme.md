# Vibe

A form.surf model repository: the vibe program's claims, results,
experiments, objections and open problems, imported from its research
database (https://github.com/cluesurf/vibe, `research/` and `test/registry.csv`).

Written by its originator, Lance Pollard. The records are generated by an
importer and never edited by hand. Every imported record carries
`provenance.tool: "importer_vibe"` and `ai_written: false`. The
records whose words a model wrote (the account in `paper/account.md`,
this file, `AGENTS.md`, the hypothesis statement of each negative
result, and the nine questionnaire answers) say `ai_written: true`.
No record is reviewed.

The questionnaire answers are the one part the research database does
not hold. They are written separately, each quoting the vibe readme or the clue.surf vibe
pages, and each quote is checked against its source on every run.

## How to read the labels

- **epistemic_status**: how the claim was reached (observed, inferred,
  hypothesized, designed, simulated).
- **standing**: the repository's own verdict. `open` for every claim
  that holds or is untested, `rejected` for every negative result,
  broken claim and refuted prediction, with the observation that failed
  it. Nothing here is `integrated`.
- **voice: critique**: an objection the program met or found in its own
  audits, linked `weakens` to the claims it targets. A claim an
  objection still stands against has `status: "disputed"`.
- **status: retracted**: a passage of a published paper that claimed
  more than its code supports, with the audit's regrading.
- Experiments are `procedure` records: `completed` when a result rests
  on them, `designed` for the rest of the registry.

## Corrections

Open an issue or a pull request against the vibe research database,
not against these files: the importer regenerates this repository from
it. Format: form.surf/1, specified at https://form.surf/guides/developers/format.
